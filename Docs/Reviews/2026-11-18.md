# Architecture review, 2026-11-18

Range: 2026-11-11 to 2026-11-18. Commits since the last review: Wbskt 271, Console 17, Python 14, .NET 20, Arduino 11, admin 42, site 13.
Production numbers: not available (code only). The export asked for in #619 is not in yet, so every index and lock finding comes from the code alone.

Follow-ups epic: #938.

This was a whole-area review, started by hand: 20 lanes (README section 2) each read their whole area from the product, architecture and senior developer angles, and one merge step removed duplicates, re-checked the P1s and the medium-confidence P2s, and ranked. Previous review: [2026-11-11](2026-11-11.md) (epic #730).

## Summary

A week of 388 commits brought the workflow lifecycle (enable, disable, deprecate), the platform admin, the offline command queue and fixes for most of the 11 Nov findings; those fixes hold where the lanes checked them, and four of the open small-items issues can now be closed or trimmed. The 20 lanes raised 327 findings. After merging the ones two or three lanes found there are 296: 4 P1, 70 P2 and 222 P3. The four P1s are each cheap to fix: publishing from the console designer has failed with a 400 since the API made `enable` required (finding 2); commands reach devices as a JSON string the documented device code cannot read (finding 1); a sub-workflow step can start a workflow in another tenant's workspace (finding 3); and the Arduino library never completes a connection on a real ESP32 (finding 4). Three of the four share one cause: a contract or a dependency is copied by hand into another repo, or tested against a fake, so one side changed and every CI stayed green. On the product side the console has fallen well behind the API: password change, sessions, queued commands, credit caps, permissions and the email-change links all exist in the backend with no screen, and mails already send people to those missing pages.

- **Every P1 was re-read in the code by the merge step:**
  - Finding 1 (payload as a string). `PayloadFor` returns the command's text for any command that is not a platform command, and `ProtocolJson.Serialize` writes an `object` holding a string as a JSON string, so the frame is `"payload":"{\"on\":true}"`. The code comment says this is deliberate. It still breaks the promise: Client.Protocol.md says the payload is a JSON value, Python's `message.payload["on"]` raises `TypeError` on a `str`, and ArduinoJson reads `null` from a string, so the README samples of all three SDKs do nothing. Credits and metering had it at medium confidence; the cross-workspace start is now confirmed, so it is high. Read against WebSockets 2.7.x: `isConnected()` is true only in `WSC_CONNECTED`; `loop()` connects and sends the upgrade in one call and reads the 101 only on a later call; `WbsktClient` checks `isConnected()` straight after that first call, fails the attempt and stops calling `loop()`. `begin()` sets the TLS client pointer to `NULL` without deleting it, so each retry leaks it. Holds. Nobody has flashed a board yet, so this is from the code.

## By angle

**Product** (90 findings). The console has fallen behind the API, and the backend now promises screens the console does not have. Password change and the session list (finding 12), queued commands and their cancel (finding 26), the credit cap (finding 24), the permissions endpoint (finding 42), Telegram chat discovery (finding 37), the message-types endpoint (finding 124) and policy deletion (finding 122) all exist in the API with no screen. Mails and refusals already link to missing pages: the email-change "Undo this change" link opens a blank page (finding 11), and the cap and plan mails point at settings that do not exist (findings 24 and 74). The second theme is promises the code breaks: the documented device code cannot read a command (finding 1), the site's headline automation cannot be built (finding 56), the first rule it teaches burns Free's month in a day and a half (finding 57), the billing policy says runs already going finish (finding 22), the privacy page says deletion removes everything (finding 39), and the site and the libraries still point at the dev hosts (finding 58). The third is errors that say what failed but not what to do: a locked account is told its password is wrong (finding 5), three different credit stops all read "Credit budget exhausted" (finding 23), a Python client that cannot connect prints nothing (finding 46), and a board refused for the plan's client limit leaves no trace in the console (finding 73). Each library's first run has a trap: Arduino never connects (finding 4), the .NET quick start exits at once (finding 53), Python registers a second client after a secret rotation (finding 44).

Patterns worth extracting: (1) one list of every link the backend puts in a mail or an error, checked in console CI against its routes, plus a catch-all not-found route; (2) a console `WorkspacePermissionsService` with `can(permission)` that every action button reads, instead of each screen learning from a 403 toast; (3) one table of refusal codes with a "what to do" line, from which the API messages, the SDKs' exceptions and the site's error pages are generated; (4) every README sample built and run in CI against the dev stack, as the Python one is not and the .NET one exits.

**Architecture** (68 findings). The biggest theme is contracts copied by hand across repo boundaries. The console's API models are written by hand, so a newly required field broke publish (finding 2) and a renamed field makes disabled workflows look live (finding 71); the admin keeps its own copies of the internal admin contracts and has already lost `KeepSubscription` (finding 62); the .NET SDK's copy of the protocol types has drifted (finding 246); the site keeps hand copies of five backend tables (findings 262 and 72); plan limits are written in five places (finding 100). Each repo's CI is green because it tests against its own copy. The second theme is isolation checked path by path rather than by structure: a sub-workflow is found by ref alone (finding 3); `users.manage` in one workspace grants ownership and delete (finding 14); the last-administrator guard covers one permission (finding 15); staff suspensions, sign-out and password changes never reach the management host's access cache or the open live feed (findings 16 and 31). The third is after-commit side effects done four ways (the auth outbox, the management host's direct bus, controller attributes, the staff runner), and each loses something: the "invitation expired" entry (finding 212), the workspace made at sign-up (finding 90), events after 50 unreadable outbox rows (finding 40), management events on a restart (finding 157). The fourth is ends that do not finish cleanly: workspace deletion leaves devices and workflows behind (finding 39) while account deletion takes the payment records with it (finding 20); an engine stop re-runs steps that already sent (finding 34); a deploy is cut off mid-migration (finding 68) or races another deploy on the same VM (finding 67).

Patterns worth extracting: (1) generate rather than copy: console models from the OpenAPI snapshots (for example `openapi-typescript`, checked in console CI), the admin on the `*.Models` packages or a generated client, the site's error, permission and plan tables from a JSON export the backend writes; (2) one workspace reference check that every id in a workflow definition goes through, and the workspace inside every trigger key built from a ref; (3) one `IAccessChangeAnnouncer` called by the service layer on every path that changes a membership, role, session or account, replacing the `[AnnouncesWorkspaceAccessChange]` controller attribute; (4) one transactional outbox in `Wbskt.Infrastructure` for every host, which skips rows it cannot read and exposes a backlog metric; (5) a drain-on-stop base for hosted workers (stop intake, await in-flight work under a grace token, write outcomes with `CancellationToken.None`) and a VM-side lock shared by the three deploy workflows.

**Senior developer** (138 findings). Most are small and repeat across lanes, which is the useful part: fix the pattern once. The clock is the most repeated: identity, tenant, workspace and device services read the wall clock instead of the injected `TimeProvider` (finding 79), credit procedures still use the SQL clock (finding 109), and no host registers `TimeProvider` itself (finding 150). Next are round trips that return what the caller already had: user rows read back to recover a RefId (finding 78), references resolved before a procedure that checks them again (finding 209), the definition read three times to open one run and once per version per list page (findings 186 and 169), four requests for one policy's counts (finding 115), members fetched four times (finding 219), the whole roster refetched for every new board (finding 123). Then code copied instead of shared. In SQL: the last-administrator guard in eight procedures (finding 210), the permission precedence three times (finding 94), run status lists in 17 procedures (finding 203), the credit post copied into `Run_DeleteRetired` (finding 108). In C#: the re-enter-password check three times (finding 77), the auth controllers' helpers twice (finding 80), the shared-key check three times (finding 152), four integration executors (finding 189), 40 lines in each `Program.cs` (finding 153). In the console: `str()` nine times (finding 191), `isRecord` seven (finding 138), three date formatters (finding 220), four page models (finding 222). Dead code and shims have piled up: nine unused procedures (finding 195), rollout shims past their release (finding 202), the pre-#306 token readers (finding 156), unused shared components and 50 unused tokens (findings 224 and 227). Finally, tests that test a fake: two of the four P1s passed CI because the Arduino shim and the conformance fake gateway behave unlike the real thing (finding 55); .NET has no test over a real connection (finding 250), Python never runs against the real hosts (finding 237), and the admin's SQL runs in no test (finding 277).

Patterns worth extracting: (1) register `TimeProvider` once in `WbsktHost.CreateBuilder`, pass `@Now` into procedures that decide on time, and add an architecture test that bans `DateTime.UtcNow` and `TimeProvider.System` in hosts; (2) procedures that return what the caller needs next (the RefId, the new id, the counts) and a light ownership read instead of the detail page; (3) SQL inline functions for the run status sets, the last-administrator guard and the permission precedence; (4) one console members directory, one `listAll` pager, one date formatter, one `node-config.util`, all in `shared/`; (5) faithful fakes (the Arduino shim, the conformance gateway) and all three libraries in the nightly live suite.
