  2. User Interaction & Flow

  Here’s a typical user journey for creating a new workflow:

   1. Login & Navigation: The user logs in and is taken to the Dashboard. They click on "Workflows" in the left sidebar.
   2. Initiate Creation: On the Workflows List Page, they click the "Create Workflow" button.
   3. Enter the Builder: They are now on the Workflow Editor Page.
       * Name the Workflow: They first give the workflow a name, like "Notify on new GitHub push."
       * Select a Trigger: In the left-side panel of available nodes, they select the "Webhook" trigger. The canvas automatically displays the unique webhook URL for them to copy.
       * Add an Action: They drag a "Make HTTP Request" action from the side panel onto the canvas and draw a line connecting the Webhook trigger to it.
       * Configure the Action: They click the "Make HTTP Request" node. The right-side configuration panel populates with fields for URL, Method, Headers, and Body. They can use data from the trigger (e.g.,
         {{trigger.body.repository.name}}) to dynamically construct the request.
       * Add Logic: They drag an "If-Condition" node onto the canvas and connect the HTTP action to it. They configure it to check if the HTTP response was successful (e.g., {{steps.http_request.statusCode}} ==
         200).
       * Add Branches: They drag two "Send Email" actions onto the canvas. They connect the "success" path of the If-Condition to one, and the "failure" path to the other, configuring different email subjects for
         each case.
   4. Save and Enable: The user clicks "Save". A toggle switch appears, which they click to enable the workflow.
   5. Testing: The user copies the webhook URL and configures their GitHub repository to send a POST request to it on a push event.
   6. Monitoring: They push a change to their repo, then navigate to the Executions page in the UI. They see a new entry for their workflow with a "Success" status, confirming everything worked as expected.
